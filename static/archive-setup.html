1. Locate NAS storage

Use a permanent local mount path, not an smb:// URL. SMB/CIFS and NFS are supported; desktop GVFS mounts are only suitable for testing.

Choose the existing MIGA backup root or a dedicated new folder. Inspection is read-only; initialization only happens after confirmation.

NAS is not mounted?

Mount it through your Linux administrator or existing SMB/NFS setup, then refresh checks. This guide does not store NAS passwords or silently change /etc/fstab.

2. Register or reuse source devices

Device ID identifies the COMPUTER, not its Linux username. Master and Slave can both use miga.

Add another device

Not sure about the folder? Enter the likely path; step 3 discovers common Data_log locations once SSH is connected.

Edit / disable / remove devices in management. Removal does not delete NAS backups.

3. Check SSH and data folders

First-time SSH preparation — local LaunchUI

  1. On the SOURCE, run ./launch_code --archive, choose Prepare this source computer, select Data_log and click Prepare SSH / rsync. Approve sudo in its terminal.
  2. On the SERVER LaunchUI, choose Archive Server / SSH Guide → Reload devices → Pair / reuse existing SSH. Working connections are reused unchanged.
  3. For a new host, compare the fingerprint with Show this source host fingerprint. Enter passwords only in the native terminal. Alternatively, copy the server public key and authorize it in the source LaunchUI.
  4. Return here and click Test / discover. For unreadable nested files, the source tab offers a separately confirmed read/traverse ACL repair.

This page never receives SSH/sudo passwords, installs keys or changes services. A changed host key is never automatically trusted.

4. Backup and verify

The unchanged backup engine processes all eligible completed runs and skips unchanged backups. This is NOT a small sample transfer. Full checksum verification can take a long time.

View detailed progress and each device’s Archive / Collections.

5. Start automatically

The server is already running. For daily use, open ./launch_code --archive on the server.

  1. Use Start server / Stop gracefully / Open management. Closing LaunchUI does not stop a detached server.
  2. Enable startup service installs a systemd user service, preserving NAS/configuration/keys. It does not interrupt the current server.
  3. Optionally choose Enable before-login startup and approve sudo. User services may then continue after logout.
  4. After reboot, check the NAS mount, service and backups. Desktop-only mounts are not suitable for unattended startup.
